Changes explained

C1Breeding-site terminal reward is no longer overwrittenIssue 1

Where: BackwardIteration(), line 549 · hunk 11

The terminal reward (TR) is set for the breeding site on every day, but the backward loop over sites also included the breeding site. For every day before MaxT its value was replaced by the value of foraging or flying on from there, so the TR survived only at MaxT (where the time reward is 0). The arrival window reached the decisions only indirectly, through same-day flights (see C2). The breeding site is now absorbing: the loop stops at NSites - 1. The forward simulation already stopped individuals at the breeding site.

−for (int site = 0; site < sdp::NSites; ++site)
+for (int site = 0; site < (sdp::NSites - 1); ++site)

C2Flights last whole days (rounded up)Issue 2

Where: Flying() line 395, simFlying() line 815 · hunk 7 hunk 17

Within one day the backward iteration computes the sites one after the other. A flight shorter than one day was valued partly with the destination’s value on the same day. For destinations with a higher index that value was not computed yet (still 0); for lower indices it was already computed. The value of a flight therefore depended on the order of the sites. Example from the test run: wintering site → hex 678 (0.16 days) was valued 0.49 instead of about 3.0, because the same-day value read was 0. The backward iteration also interpolated between days, while the forward simulation rounded to the nearest day, so the two used different flight durations. Now every flight lasts ceil(duration) days (0.16 → 1, 1.3 → 2) in both, and only completed days are read.

−t = (double)(time) + (distance / sdp::speed);
+t = (double)(time) + std::ceil(distance / sdp::speed);

C3Fixed flight reserve: f is a share of MaxXIssue 3

Where: Flying() lines 381–390, simFlying() lines 802–809 · hunk 6 hunk 7 hunk 17

Before, only f · x was used to compute the range, and after the flight only the remaining part of it was returned: the unused (1 − f) · x disappeared. With f = 0.5 every flight cost at least half of x, even over zero distance. Now (1 − f) · MaxX is a reserve that is never used for flight; the fuel is max(0, x − reserve), and the reserve is kept after the flight. A flight is impossible when the distance exceeds the range. With f = 1 the reserve is 0.

−double usableF = f * x / sdp::MaxX;
−...
−nextx = ((Sqr_c/Sqr_ca) - 1.0) * sdp::MaxX;
+double xReserve = (1.0 - f) * sdp::MaxX;
+double usableF = std::max(0.0, (double)(x) - xReserve) / sdp::MaxX;
+...
+nextx = xReserve + ((Sqr_c/Sqr_ca) - 1.0) * sdp::MaxX;
+...
+else if (distance > range) interpolReward = 0.0;

C4Predation is computed from the food gain, the same way in both directionsIssue 4

Where: Foraging() lines 303–337, simForaging() lines 751–757 · hunk 3 hunk 4 hunk 5 hunk 16

In the backward iteration, Predation() received the fitness of the option (about 3–5) where it expects the food gain per day. It now receives mean (the food gain). In the forward simulation the risk formula used the gross gain; it now uses the same net gain as the backward iteration (intensity × gain − expenditure, set to a tiny positive value if ≤ 0) in both terms of the formula. The effect on results is small, because x is much larger than the daily gain.

−f1 = (1.0 - Predation(time, site, x, u1, f1)) * f1;
+f1 = (1.0 - Predation(time, site, x, u1, mean)) * f1;

C5Round() is correct for negative valuesIssue 5

Where: Round(), line 85 · hunk 2

(int) truncates towards 0, so the old function gave −0.3 → 1 and −1.7 → −1. No effect in the test run, but it matters when x can become negative before rounding.

−if (value - floor(value) < 0.5) return (int)(value);
−else return ((int)(value) + 1);
+return (int)(floor(value + 0.5));

C6The rest of a flight day costs the ground expenditureFound in testing

Where: Flying() line 398, simFlying() line 810 · hunk 7 hunk 17

With whole-day flights, the part of the last flight day not spent flying cost no energy and carried no risk. A 175 km flight cost 4.6 units of x, while a day on the ground cost 5.96, so short flights back and forth were cheaper than staying. The rest of the day is now charged at the daily ground expenditure, proportional to the time left.

+nextx -= sdp::expend(dep_site, time) * (std::ceil(distance / sdp::speed) - distance / sdp::speed);

C7Flight mortalityNew parameter

Where: Flying() line 424, simFlying() line 811; Init()/InitSim() argument flightMort · hunk 1 hunk 8 hunk 9 hunk 10 hunk 14 hunk 15 hunk 17

Flights had no mortality risk. Now the survival during a flight is 1 − flightMort × flight days (actual flight time, distance / speed): the backward iteration multiplies the value of the flight by it, and the forward simulation draws death during the flight. Default in the R wrapper: flightMort = 5e-4 per day of flight, the same order as the daily predation risk at stopovers (about 1e-4 to 1e-3 with the default predation parameters).

+interpolReward *= (1.0 - sdp::flightMort * distance / sdp::speed);

C8Stay rule: ties between staying and flying are resolved as stayingNew parameter

Where: BackwardIteration() lines 617–624; Init() argument stayThresh · hunk 1 hunk 9 hunk 10 hunk 13

Early in the season many states have exactly the same value for foraging and for flying to a nearby site. Decision error turns such ties into 50/50 choices, and the simulated birds flew back and forth between the wintering site and a nearby hex for weeks. Now the bird stays unless flying is better than foraging by more than stayThresh (relative), and the value of the state is then the foraging value. Default stayThresh = 1e-5. Thresholds from 1e-6 to 1e-4 gave the same results; from 1e-3 the rule starts to block decisions with real differences.

+if (help_flying > 0.0 && (help_flying - f_help) / max_Reward <= sdp::stayThresh) {
+ sdp::PMatrix1(site, time, x) = 1.0;
+ sdp::PMatrix2(site, time, x) = 0.0;
+ sdp::FMatrix(time, site, x) = f_help;
+}

C9No default flight destination when no site can be reachedIssue 6

Where: BackwardIteration() lines 595–611 · hunk 12 hunk 13

When no destination could be reached, the best destination stayed at its default, site 0 (the wintering site), and decision error gave it a small probability (about 2.5e-4). Now the destination is NaN and the probability of flying is 0; the R wrapper falls back to foraging if it ever meets a NaN destination.

+if (help_flying <= 0.0) {
+ sdp::DMatrix2(site, time, x) = arma::datum::nan;
+ sdp::PMatrix1(site, time, x) = 1.0;
+ sdp::PMatrix2(site, time, x) = 0.0;
+} else { ... }
